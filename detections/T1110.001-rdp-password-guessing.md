# Detection Rule: RDP Password Guessing (T1110.001)

## 1. Rule Metadata
- **Rule ID:** `SOC-WIN-001`
- **MITRE ATT&CK:** `T1110.001` — Brute Force: Password Guessing
- **Severity:** High (Blocked) / Critical (Succeeded)
- **Data Source:** `index=wineventlog` (Windows Security Event Log — `EventCode=4625`, `EventCode=4624`)
- **Target Platform:** Windows 11 Pro (`ws01` / `10.10.10.30`) with Network Level Authentication (NLA) enabled
- **Status:** Validated

## 2. Description
Detects automated or manual password-guessing bursts over Remote Desktop Protocol (RDP) with Network Level Authentication (NLA) enabled by correlating rapid bursts of failed network logons (`EventCode=4625`, `LogonType=3`) with subsequent successful logons (`EventCode=4624`, `LogonType=3` or `10`) from the same source IP address (`IpAddress`) and target user (`TargetUserName`) within a 5-minute window.

## 3. Splunk SPL Query
```spl
index=wineventlog EventCode IN (4624 4625) LogonType IN (3,10)
| bin _time span=5m
| stats count(eval(EventCode=4625)) as Failed
        count(eval(EventCode=4624)) as Successful
        values(WorkstationName) as WorkstationName
        values(SubStatus) as SubStatus
        values(LogonType) as LogonType
        by _time, IpAddress, TargetUserName
| where Failed >= 4 AND IpAddress!="-"
| eval Alert_Status = if(Successful > 0, "CRITICAL - Brute Force Succeeded", "HIGH - Brute Force Blocked")
```

## 4. Detection Logic & Threshold Rationale
- **NLA Authentication Mechanics (`LogonType=3`):** With NLA enabled, failed RDP credential checks log as `EventCode=4625` with `LogonType=3` (Network) rather than `LogonType=10` (`RemoteInteractive`). Including `LogonType IN (3,10)` captures both NLA authentication attempts and any follow-on interactive desktop session (`LogonType=10`).
- **Time Bucketing & Threshold (`5m` / `Failed >= 4`):** Grouping into 5-minute buckets (`bin _time span=5m`) and alerting on `Failed >= 4` catches low-volume targeted bursts (such as 4–5 attempt tests) while filtering out 1–2 accidental user typos.
- **Outcome Classification:** Evaluating `Successful > 0` separates blocked guessing runs (`HIGH`) from confirmed credential compromises (`CRITICAL`) inside a single correlation rule.

## 5. False Positives & Tuning
- **Legitimate User Typos:** Users mistyping their password multiple times in rapid succession will trigger `HIGH` alerts if they reach 4 failures within 5 minutes.
- **Cached SMB / Mapped Drive Credentials:** Because SMB also generates `LogonType=3` `4625` events under NTLM, misconfigured services or stale cached credentials on network shares can produce similar bursts. Check `WorkstationName` and correlate with `Microsoft-Windows-TerminalServices-RemoteConnectionManager/Operational` (`EventCode=1149` on successful NLA) during triage.

## 6. Analyst Triage Playbook
1. **Check Account Validity (`SubStatus`):**
   - `0xc000006a`: Valid username, wrong password (confirms the targeted account exists).
   - `0xc0000064`: Non-existent username (indicates username enumeration/spraying).
2. **Inspect Source Hostname (`WorkstationName`):** Offensive tools such as Hydra pass the attacker's local hostname (e.g., `kali`) in the NTLM negotiation.
3. **Verify Interactive Follow-Through (`Successful > 0`):**
   - Pivot to `index=wineventlog` for `EventCode=4624` with `LogonType=10` (`RemoteInteractive`) from the same `IpAddress` to determine if an interactive GUI session was opened after NLA authentication.
   - Pivot to `index=sysmon` for process creation (`EventCode=1` such as `rdpclip.exe`, `cmd.exe`, `powershell.exe`) after the `4624` timestamp.

## 7. Containment & Remediation
- Block the offending source `IpAddress` at the host or perimeter firewall.
- Force an immediate password reset for the compromised `TargetUserName` and verify local/domain account lockout policies (`net accounts`).
- Audit open or disconnected RDP sessions (`qwinsta`) and terminate unauthorized sessions (`rwinsta`).
- Hunt for persistence mechanisms created after the successful logon (`EventCode=4720` new users, `4698` scheduled tasks, `7045` services).
